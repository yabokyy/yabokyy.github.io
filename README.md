# yabokyy.github.io

Личная страница на Jekyll с собственными шаблонами и оформлением.
Minima остаётся установленной как базовая тема, но основные страницы используют
локальные шаблоны и CSS вместо её стандартного оформления.

Адрес сайта после публикации: <https://yabokyy.github.io>

На главной — приветствие, ссылки на профиль, проекты по категориям и блок контактов.
Сайт всегда использует тёмную тему независимо от настроек системы.
На телефоне блоки и карточки располагаются в одну колонку.

## Технологии

- Ruby и Bundler — среда выполнения и управление зависимостями.
- Jekyll — сборка сайта из Markdown и HTML.
- Minima 2.x — базовая тема; HTML и CSS оформления находятся в репозитории.
- GitHub Pages и GitHub Actions — хостинг и публикация.

Зависимости описаны в [Gemfile](./Gemfile).

## Локальный просмотр

Нужны Ruby и Bundler. На Windows можно использовать RubyInstaller с Devkit
либо WSL. Версия Ruby должна быть совместима с `github-pages`;
локальная сборка в текущем окружении пока не проверена.

Из корня проекта выполните:

```sh
bundle install
bundle exec jekyll serve
```

Откройте <http://localhost:4000/>.
После изменения конфигурации перезапустите сервер.
Созданный при установке `Gemfile.lock` следует сохранять в Git.

## Что редактировать

- Имя, описание сайта и профиль GitHub — [_config.yml](./_config.yml).
- Краткое представление под приветствием — [index.md](./index.md).
- Подробный рассказ о себе — [about.md](./about.md).
- Порядок блоков главной — [_layouts/home.html](./_layouts/home.html).
- Меню, общие метаданные и подвал — [_layouts/default.html](./_layouts/default.html).
- Цвета, размеры, отступы и мобильное расположение — [assets/css/site.css](./assets/css/site.css).

Цвета тёмной палитры заданы CSS-переменными в блоке `:root` в начале таблицы стилей.
Декоративная монограмма `y_` создаётся HTML и CSS в шаблоне главной.
Её можно заменить собственной фотографией.

Навигация сейчас задаётся непосредственно в общем шаблоне.
Параметр `header_pages` Minima не управляет этим меню.

## Добавление проектов

Добавьте запись в [_data/projects.yml](./_data/projects.yml):

```yaml
- name: Название проекта
  category: Веб
  symbol: "</>"
  description: Короткое описание проекта.
  url: https://github.com/yabokyy/имя-репозитория
  tags:
    - Jekyll
    - CSS
```

Проекты автоматически группируются по `category`. Порядок записей определяет
порядок карточек; категории появляются в порядке первого упоминания.
Сейчас добавлена карточка самого сайта, без вымышленных работ.

Для обложки положите файл в [assets/images/](./assets/images/) и добавьте
к записи проекта поле `image: /assets/images/название.jpg`.
Документы можно хранить в [assets/files/](./assets/files/).
Все эти материалы будут доступны посетителям сайта.

Картинка и ссылка на документ внутри Markdown-страницы:

```liquid
![Описание изображения]({{ '/assets/images/avatar.jpg' | relative_url }})
[Скачать резюме]({{ '/assets/files/resume.pdf' | relative_url }})
```

Примеры сработают после добавления соответствующих файлов.

## Проверка

Перед коммитом последовательно выполните обе команды и убедитесь,
что каждая завершилась успешно:

```sh
bundle exec jekyll doctor
bundle exec jekyll build --trace
```

Отдельные тесты и линтеры не настроены. В браузере проверьте главную,
страницу «Обо мне», страницу `/404.html` и ссылки.
Проверьте узкий экран и навигацию клавишей Tab.
Для оформления и работы страниц JavaScript не требуется.

Каталог `_site/` содержит результат сборки: вручную его не редактируют
и в Git не добавляют.

## Публикация

В GitHub выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**.
Существующий [workflow](./.github/workflows/jekyll-gh-pages.yml) публикует сайт
после отправки изменений в `main`; также доступен ручной запуск во вкладке Actions.
Проверьте успешное завершение workflow перед просмотром опубликованного сайта.
